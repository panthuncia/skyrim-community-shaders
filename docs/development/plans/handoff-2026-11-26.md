## 3. The roadmap: decisions already made

Read [render-thread-snapshots.md](render-thread-snapshots.md) in full. The user settled:

1. **Fully asynchronous pacing.** The render thread runs as fast as the GPU allows; the game thread publishes snapshots
   whenever it has new data. Neither waits on the other. A separate **update-rate cap** setting (default 60 updates/s)
   paces the game thread once the engine's Present no longer blocks it.
2. **Port first.** Native must ignore the game's renderer entirely. Latching engine draws, reading engine-bound GPU state
   or calling engine render functions for side effects does not count as done.
3. **Scaleform: a full native UI renderer**, a 1:1 port of the game's renderer (same shaders, same calls) as ORG/BasicRHI
   passes.
4. **Guest mode is out of scope.** It stays on the main thread (D3D11 mods must order with CS's draws). Only native moves.
   Feature code is shared, so the snapshot model has two producers: native's capture from game data, guest's capture at
   today's hooks.
5. **Frame generation multiplies the render rate**; snapshots carry data only and play no part in timing.
6. Visual-only animation between snapshots, and each engine side effect's fate, are decided per feature during its port.

## 4. Where to start: phase 0

The roadmap's phase 0, in order:

1. **The `FrameSnapshot` contract** (types, ids, the per-feature block shape, events since the previous snapshot,
   publication and adoption points). Start from DCLF's `Scene::FrameInputs` / `ScenePublication` and the frame anchors'
   latch path (`RenderGraph/FrameAnchors.cpp` `TapDeclared`, `SharedConstants`, `Stage.CopyLatch`).
2. **The live-read detector**: generalise `FrameGlobals::TakeUnscopedReads` (`Core/Shading/FrameGlobals.h:106`) to the
   engine singletons CS reads; it is phase 1's progress metric.
3. **The engine-render detector** for native: count engine render functions entered in a native frame (the engine zones
   table `src/EngineZones.cpp` already wraps the call sites).
4. **The cadence test mode**: render each snapshot several times, or drop snapshots, on one thread.
5. **The side-effect inventory**: every engine render-half write the game reads (visibility `kAccumulated`, fades, the sun
   query, decals, facegen, water, shadow bookkeeping), with who reads it.

Phase 4 (the native UI renderer) is self-contained and can start right after phase 0, alongside phases 1-3. The roadmap's
"Watch list" table lists the cadence assumptions found, with file references.
