## 2. User preferences and rules

- Conventional commits, title of 50 characters or less, body wrapped at 72, no attribution lines. Push to `org_integration`.
- Report design changes explicitly. Give recommendations, not surveys.
- The direction is fully native: compute engine draws from engine data, stop capturing engine draw calls. The memory file
  `fully-native-direction.md` has the details.
- To diagnose rendering bugs, read back the intermediate buffers rather than bisecting commits. Useful switches:
  - `CS_ORG_SHOT_TARGET=<n>` reads back an engine render target (`kMAIN`=1, `kUNDERWATER_MASK`=12, `kRAW_WATER`=88,
    `kSSR`=109).
  - `CS_ORG_SHOT_PHYSSKY=apshadow` reads back Physical Sky's AP shadow.
- When the user asks for something without teleports, don't use `coc`, `moveto` or `setpos`.
- "Static water" reports: check the timescale first. A timescale of 0 stops the flow.

## 4. Traps found this session

- **`cs-test stage` does not copy DXVK.** After any DXVK change, copy `extern/dxvk/build/src/d3d11/dxvk_d3d11.dll` and
  `src/dxgi/dxvk_dxgi.dll` into `C:\Modding\MO2\mods\CS AB nfg\SKSE\Plugins\CommunityShaders\bin\` by hand. A stale copy shows
  up as a slow DCLF pipeline precompile (17 s instead of under 1 s) and odd guest-mode faults.
- **Ghidra MCP** (`http://127.0.0.1:8089`): both AE and SE are open.
  - Always pass `&program=/skyrim/ae/SkyrimSE.exe.unpacked.exe` (or `/skyrim/se/...`); the current program may be either.
  - Endpoints: `decompile_function`, `disassemble_function`, `get_function_by_address`, `get_xrefs_to`, `read_memory`,
    `list_open_programs`.
  - Address-library helpers in the session scratchpad (`addrid.py` maps address to id, `id2addr.py` id to address). They wrap
    `BethesdaGhidraScripts/scripts/commonlibsse/address_library.py` over `BethesdaGhidraScripts/addresslibrary/sse/*.bin`;
    rewrite them if the scratchpad is gone.
  - Matching AE to SE: compare vtable slots (CommonLib's `VTABLE_*` ids give both runtimes), or the readers and writers of a
    global.
- **Finding an engine writer:** an in-process hardware write watch works. Set DR0 plus DR7 on every thread from a helper
  thread, and log the faulting RIP and a stack from a vectored exception handler. Scanning the raw stack for return addresses
  crashed once: read only within the thread's stack limits.
- **New engine-write hooks belong in SceneWriterFramework** (`extern/SceneWriterFramework`):
  - Add the hook id in `swf.h`, the hook and its plan entry in `src/families/Calls.cpp`, and the ids in
    `src/tables/Ae_1_6_1170_Hooks.cpp` and `Se_1_5_97_Hooks.cpp` (AE 1.7.104 reuses AE's ids). Update the tests and
    `CHANGELOG.md`.
  - Build `build/vs` with `cmake --build build/vs --config Release`, then run `ctest --test-dir build/vs -C Release`.
  - Run `swf_table_check` against `BethesdaGhidraScripts/exes/skyrim/{se,ae,ae17}/SkyrimSE.exe.unpacked.exe`. The 1.7.104
    address library is in `C:\Modding\MO2 1.7.104\mods\Address Library for SKSE Plugins\SKSE\Plugins\`.
  - DCLF subscribes with `SceneWriter::SubscribeCall`.
- **A cold shader cache** (the first run after toggling a feature) takes about 2 minutes of loading screen: the SPIR-V compiles
  finish about once a second. This is expected now. To get a cold cache, toggle a feature combination you haven't used before.

## 5. Open items

Water:

1. **Two water constants differ from vanilla.** D3D11 writes ReflectionColor.w as the timer minus a constant, and FresnelRI.x
   as 0. The water port writes the raw timer and the material's 0.1. Vanilla's SetupMaterial writes the raw timer, so something
   later rewrites it, and that writer hasn't been found (a write watch would find it).
   `docs/development/plans/dclf-water-indirect.md` section 13 still states the old, wrong conclusion and needs correcting.
2. **Underwater mask clear in native mode:** the engine's clear of `kUNDERWATER_MASK` has no graph pass, so native mode may
   never clear it.
