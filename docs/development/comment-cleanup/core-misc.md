# Comment cleanup notes: core-misc

Paths are relative to `src/Features/DrawcallLimitFix/` unless they start with `DrawcallLimitFix.`, which are in `src/Features/`.

## 1. Simplification or documentation targets

- Api/ObjectContributors.h, file header and section 2 enums. The header was a 35-line map of five contribution kinds, which Core query reads each one (TechniqueObjectFlags, PropertyFlagRules, GeometryTypeOn, ... EntryClassTaken), and a three-step recipe for adding a Core class ("its value in the enum here, before Count ...; Core's test of it where Core decides, through the Extensions query above (Core names the value, never the feature); the feature's registration of it, under its toggle"). Five kinds of membership (engine key, parent, object class, entry class, owner class, plus views) each with its own struct, enum and Extensions query, is hard to hold in your head. Suggest: either fold the membership kinds into one "class id + toggle + optional predicate data" registration, or move the recipe and the map of which query reads which contribution into a DCLF extension API doc.
- Api/ObjectContributors.h, GeometryTypeContribution. One struct carries five unrelated jobs (toggle gate, property-flag LOD filter, FrameValues item class, per-frame mover, entry-class rule, index ranges callback). The comment was 25 lines explaining how each field reaches a different Core stage. Suggest splitting into separate registrations (geometry membership, entry rule, ranges source).
- Api/ObjectContributors.h, UnheldRootsContribution. Lifetime contract for engine-owned parentless roots (no references kept, every exit must be an event, enter/leave bracket around gather and mirror pushes, owner child edits counted apart by SceneTracker::UnheldEdits). This is an unexpected interaction between engine refcounting, the tracker and the feature's hooks; it needs a doc section.
- Api/Feature.h InstallContext. Every Register* method carried a doxygen list of the exact conditions that fail the install (register ranges, slot counts, uniqueness, callback presence). That duplicated the validation code in Extensions::InstallFeatures and drifted easily. Cut to one line naming the main rule. Suggest: make the install failure messages self-explanatory and treat the validator as the reference; one notable hidden rule was RegisterPass: "a second pass with a latch word, or one scheduled anywhere but in main.depth before core.z.build-draws" fails.
- Api/Feature.h Feature::sourceHooks / earlyHooks / preflight. The original explained four install phases at PostPostLoad (preflight, early hooks, source hooks per ShadowSource order, install), what each may touch and in which order versus Core's own engine side. That ordering is load-bearing and only documented here. Suggest a short "install phases" section in a DCLF doc.
- Api/CoordinatorComponents.h CoordinatorComponent. 26 optional hooks in 10 sets (Slots, Residency, Accumulate, Walk, DenseWalk, Retirement, EntryClassHooks, Events, Commit, Adoption). Each original comment pinned the hook to an exact point inside coordinator internals (e.g. "right after the slot's resident position is grown, before its patch is stored"; "after allLeft and before its accumulated half is reset"; "before the set's change is noted and the claims are snapshotted"). A feature author has to know the coordinator's internals to use it, and the parity dense walk needs components to save and restore their own state. Suggest: shrink the surface (Slots vs Residency vs Accumulate overlap heavily), have the coordinator own a generic per-slot side table so components do not need save/restore around the dense walk, and document the hook order as one sequence diagram in a DCLF coordinator doc.
- Api/DrawFamilies.h DrawFamilyContribution. A 35-line block described when each of 13 callbacks runs relative to FrameDriver, PassCapture, the pipeline lane and the trees view's epoch commits, plus the faces' data layout. A family needs four callback groups (frame, main, faces, direct) and Core-side state (slot pipelines, PassCapture withholding) to draw one instanced list. Suggest a doc page "writing a draw family" with the per-frame sequence; the decide/owned split (owned exists only because decide may be skipped) could be simplified by always calling decide with an "off" flag.
- Api/ShadowViews.h ShadowExclusionContribution / ShadowListExclusion. The sun/point entry exclusion runs build (payload, per mode), publish (after the epoch draws), frameStart (rebase to the frame's candidates) and listExclusion (the primary cull's list filter), with Core holding the exclusion opaquely and the rule that a root leaves the scene lists only if its entry also leaves the cascades. Four callbacks across three threads and two Core subsystems for one verdict set is hard to follow. Suggest a short doc of the exclusion's lifetime, or making Core own the exclusion type so the feature supplies only the verdict.
- Api/Reports.h ReportPoint. 23 report points, each originally documented by its exact position among Core's own report lines ("after the light masks' line, before the frame camera's"). Placement by neighbouring line is fragile and the enum mixes thread, cadence and log-versus-text. Suggest collapsing to a few points keyed by thread and cadence (render-thread logged, async text, scene-lane), and let the report sort features' lines by name.
- Api/TableFamilies.h TableFamily. The original explained write stamps, per-object row references with bias and shift encoding, row tags (generations), retirement through SceneTables::Retire, and a change journal trimmed by commit hooks' sent epochs (TableFamilies::TakeSent) that deliberately forces no publication. That is four interacting lifetime mechanisms (stamp, tag, retire, journal) in one registration. Suggest a doc of the table family lifecycle, and consider whether the stamp and the journal could be one mechanism.
- Api/SceneResources.h SceneResources::require. A revision is kept without calling require when its witnesses of table families, vertex stream rows and posted input words did not move, so require must read nothing else; anything else must go through postInputs. That is an implicit memoisation contract that a feature author can break silently. Suggest enforcing it by handing require only a view of those inputs, not the whole tables.
- Api/Passes.h PassDef cpuPipeline / recordAtExecution / gpuLate. Three bools combine into four pass recording modes across guest (DXVK command buffer) and native, GPU-driven and CPU-driven. The original comment explained each combination in terms of ORG's late batch and DXVK's CS thread. Suggest replacing the three bools with one enum of the valid modes and documenting it in the frame graph doc.
- Api/Epochs.h EpochDef::hostedBy. A hosted epoch has a revision shape slot but no segment, recording, order or submission; its passes are listed in the host as "<id>/<key>". This is an unusual indirection that the schedule relies on. Suggest documenting hosted epochs in the frame schedule doc, or modelling them as sub-shapes of the host.
- Api/LatePoses.h LatePoseContribution. Improved Camera hides nodes by shrinking their local scale after the shadow maps and restoring it by the next frame; DCLF detects this by comparing world scales at the depth commit and applies the shrink to a second copy of placement and palette rows. The file itself says it stands in for a view-mask API. Keep as a simplification target: replace with real per-view geometry masks.
- Core/Extensions/FrameBindings.h DeclaredReads / GraphTextureIndex / EngineTargetTextureIndex / PrecipitationOcclusionTextureIndex / AdaptedLuminanceTextureIndex. Reading a published graph texture means: declare it at graph build with a matching view variant, latch the build-time bindless index at commit, re-check in Prepare, and on a miss publish or import the target so the next build declares it. Several special cases (character light luminance parity, precipitation occlusion import, tripwire-wrapped views) each have their own function. The original noted "Phase 4 of the native frame graph moves these tables into Prepare". Suggest finishing that move (org::PreparedTablePublisher) so the declare/latch/check dance and the special cases disappear.
- Core/Shading/LightingDescriptors.h DeriveLightingDescriptors and friends. The file reimplements GetRenderPasses/SetupTechnique/OnVisible decisions (hints 0/2/3/7/9/12, runtime pass bits, alpha-test lists, LOD fades) with engine addresses as the main documentation. It is the primary explanation of how DCLF predicts native passes. Suggest a dedicated engine-notes doc page per engine function (GetRenderPasses AE 0x1414adfb0, SetupTechnique, BSFadeNode::OnVisible) that this code links to, rather than spreading the reverse-engineering across comments.
- Core/Shading/MaterialSources.h MaterialSources. A 25-line comment was the main explanation of how a material record stays current without re-evaluation: four input kinds (material fields recaptured on every write, TexcoordOffset watched across the engine's per-frame buffer flip, shader-object and global values shared per signature probe, and the character light t11 view kept in the frame not the record), plus IBLParams frozen at first evaluation. Combined with MaterialPortFrame.h's FrameComponentsWitness, which deliberately leaves out values that alternate every frame, this is a subtle caching scheme. Suggest a doc section "material record freshness" and consider evaluating frame-sourced components in the draw (frame block) instead of patching records.
- Core/Shading/FrameGlobals.cpp first-person subtree (SubtreeState / SyncSubtree / NoteFirstPersonCulled). Hidden bits of the first-person skeleton differ between the frame's start and the engine's first-person culls (arms hidden at frame start while drawn), so DCLF keeps an event-driven mirror of the subtree with saved culled bits and re-reads after publication to close a race. Hard to follow from the code; suggest replacing with a per-view visibility mask from the engine side, or a doc.Core/Runtime/FrameRetirement.h retirement clock. A 15-line comment was the only explanation of why DCLF has one clock fed by two sources (graph host retired callback and the CPU pipeline's DXVK-side frame timeline), why host frame numbers must never be used (an async epoch's ticket is numbered at prepare time, so completion order says nothing), and the separate SubmittedGpuPoint vs SealedGpuPoint rules for binds vs waits (waiting on unsealed work deadlocks because it only reaches the device at the present that waits on the signal). This is exactly the kind of interaction that caused past copy-queue stalls. Suggest a doc section "retirement and GPU points", and if possible collapse the two sources into one timeline once the CPU pipeline submits through the host.
- Core/Settings/Toggles.h Toggles (requested / active / frame sets). Three toggle sets with a publication-gated handover, a thread-local snapshot scope for scene passes, and a packed 64-bit word mixing flags with CPU-pipeline state. Readers must pick the right accessor (FrameToggles vs SceneToggles vs ActiveToggles) and the rule "a toggle only takes effect once a publication is committed under it" is only stated in comments. Suggest a doc, and consider making the frame set the only one readers outside the coordinator can see.
- Schedule/Frame.cpp kMainDepth. A 17-line comment was the only explanation of the depth epoch's pass order: portal queries on the graphics queue, next-frame state on compute beside the depth draw, reflection faces between first person's cull and depth, first-person depth after the HZB and before kPOST_ZPREPASS_COPY, visibility events last because ORG starts a graphics batch at the first compute-dependent pass. Order constraints of this kind should be expressed as pass dependencies in the graph, not as list position; until then they need a doc.
- DrawcallLimitFix.h occlusion map entry points (OcclusionReady, OcclusionNeedsEngine, OcclusionCamera, OcclusionReferenceDue, OcclusionEngineOccluders, RenderPrecipitationMask, RenderPrecipitationAtShadowMaps). Skylighting, the engine's Precipitation::SetupMask/RenderMask and DCLF's shadow epoch hand the sky map and precipitation mask back and forth across three engine points, with a load-hold path and a parity reference path. The flow is only documented in these comments and is hard to follow. Suggest one owner for the maps (Skylighting or DCLF), or a sequence diagram in dclf-architecture.md "The occlusion maps".
- Core/Runtime/KeptState.h kept arrays. Chunked copy-on-write arrays with per-build journals, shared event logs, content epochs and per-holder emits; the comments were the main reference. dclf-architecture.md "Persistent draw state" exists; make sure it covers the holder/epoch protocol and the parallel-write rules (PrepareWrites, Write/WriteParts, then Mark on the owner thread in a deterministic order).

## 2. Hazards kept

- Api/CoordinatorComponents.h Commit::settle: veto changes apply in the same commit; Adoption runs on the render thread with no coordinator context.
- Api/CoordinatorComponents.h: keys/nodes handed to hooks are never dereferenced unless the coordinator tracks them (only tracked entries are known alive).
- Api/CullInputs.h: without a main cull input the primary cull stays off (scene lists keep the object root only while the walk reached unbound space).
- Api/DepthPyramid.h: mip 0 is half the depth's next power of two so a mip is picked by log2 of screen extent.
- Api/DrawFamilies.h DrawFamilySignature: SV_InstanceID counts from first instance only on Vulkan; D3D12 needs the instance word pushed (kDrawPushInstance).
- Api/EngineEvents.h StandInObserver::structure: called on any attaching/detaching thread, must be lock-free.
- Api/EngineEvents.h kNodeFieldFadeAmount: fade node fadeAmount at +0x100 (Actor::SetAlpha).
- Api/EntryRanges.h EntryRange::operator==: the engine rebuild of runs (FUN_140e31180) can return the same range with another key, so equality ignores the key.
- Api/Feature.h Feature::preflight: a hook-site conflict must leave DCLF off, not half installed.
- Api/FrameBindings.h FrameBinding::select may alternate between frames; address parity accepts either of two consecutive frames.
- Api/FrameBindings.h PerDrawBuffer: main pass holds the last drawn object's buffer, so frame blocks must not mirror it.
- Api/FrameValues.h FrameValueInput::input: released on DCLF's pool, must hold no engine reference.
- Api/FrameValues.h FrameValuePool::unorderedAccess: without it D3D12's UAV is a null view and GPU stores are silently dropped.
- Api/LightVolumes.h PointLight: values as SetupGeometry (FUN_1414df650) writes them; affectsLand at BSLight +0x61.
- Api/MainRanges.h depthPrepass: decals draw depth first so a host fragment under an opaque texel fails the colour EQUAL test.
- Api/ObjectContributors.h ShadingVariable::compared: floats past `compared` depend on native draw order, so parity skips them.
- Api/ObjectContributors.h UnheldRootsContribution: engine frees master particle roots on low refcount, DCLF must hold no reference; enter/leave bracket so no removal lands between listing and capture.
- Api/ObjectContributors.h kMaxMaterialFrameVariables: a material row has exactly this many places.
- Api/ObjectContributors.h kShadingBlockWords: frozen by DCLFObjects.hlsli.
- Api/Passes.h latchWord: BuildDrawsLatch has one stage word (byte 300); a second pass needing one must grow it first.
- Api/RootStates.h globalsKey: 32-bit FNV-1a witness formula.
- Api/ShadowViews.h OcclusionMapContribution::technique: LOD never occludes, the engine's mask cull does not visit the LOD root.
- Api/ShadowViews.h ShadowSourceHooks: point light cull hooks must install after the Sun's registration hooks.
- Api/Views.h CullHiddenSource: engine toggles hidden bits around views within a frame; membership must read the captured bit.
- Api/Views.h ViewKeyRule::cullBackFaces: cube faces mirror the image, so they cull front faces.
- Api/Views.h ViewShape::frustumCull: first person draws untested because its skinned bounds do not follow its camera.
- Core/Extensions/CoordinatorComponents.h HoldFadeNode: returns null when the entry holds another node; the render thread is asked and the component called again.
- Core/Extensions/CullInputs.h CullBindingSelect::Published: late-bound buffer lets a reader on another queue wait for the upload.

- Core/Extensions/FrameBindings.cpp PrecipitationOcclusionTextureIndex: Skylighting swaps its own twin map into the engine field while it draws; publishing it under the engine id would thrash the slot.
- Core/Extensions/FrameBindings.cpp: volk (Internal.h) must precede every Vulkan header.
